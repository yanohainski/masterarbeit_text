\begin{itemize}
    \item Das System muss die gesprochenn Inhalte Transkribieren

    \item Das System muss das Gespräch sinnvoll und ohne Informationsverlust zusammenfassen
    \item Das System muss die Informationen für alle Teilnehmer anzeigen.

\subsection{Interaktion}
Die Interaktion zwischen dem Anwender und des Meetingassistenten bildet die Schnittstelle zur Außenwelt und ist essentiell wichtig für die Benutzerfreundlichkeit des Gesamtsystems. Geplant ist die Entwicklung eines Teams Plugins, welches in der Lage ist die Informationen anzuzeigen. 
Mithilfe der Attendee API (Referenz) ist das System in der Lage Audioinhalte aus einem Teams Meeting heraus zu streamen und zur weiteren verarbeitung an ein Backend zu streamen.
größtes Problem bei der Recherche, war es zugriff auf MS Teams zu bekommen. Erstellen von Bots möglich, allerdings werden bestimmte zugriffe zurückgehalten. Z.b. Live Audio, daher gibt es nur nur eine zusammenfassung nachträglich von Teams.

Attendee arbeitet mit Broswerautomatisierung, sodass das Meeting im browser geöffnet wird über die Teams browser variante und darüber dann daten abgegriffen.

\subsection{Transkription}
Die Transkription der Audioinhalte geschieht mit eines aus dem Masterprojekt bekannten Transkriptionservices welcher selbst mit einem Docker Container gehostet wird und auf Whisper basiert. 
Als alternative kann auch ein Transcriptionservice der Attendee API verwendet werden. Diese ist in der Lage die Teams eigenen Closed Caption Transcription zu verwenden.
